# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

The primary user is a student publishing a first personal portfolio. The portfolio's
visitors are classmates, instructors, recruiters, and potential collaborators who
need a quick, credible overview of the student's interests and strongest work.

## Product Purpose

Provide an editable starter portfolio that a student can personalize and publish
through GitHub Pages. Success means the student can replace clearly marked starter
content, present a concise introduction, and guide visitors to portfolio highlights
and contact links without needing a web framework or backend.

## Positioning

The portfolio is intentionally simple to own: a small static site with readable
source files, no build step, and deployment handled by GitHub Actions.

## Operating Context

The project lives in a GitHub repository and is deployed as a GitHub Pages project
site. The student edits HTML and CSS directly, commits changes, and lets the Pages
workflow publish the site.

## Capabilities and Constraints

- Include a landing page and a few focused portfolio-highlight pages.
- Use static HTML, CSS, and minimal JavaScript.
- Use GitHub's Primer design system and follow the GitHub Brand Toolkit without
  implying that the personal site is an official GitHub property.
- Work correctly from a GitHub Pages project path using relative URLs.
- Include a GitHub Actions workflow for Pages deployment.
- Remain easy for a first-time portfolio owner to edit.
- Use clearly marked starter content rather than invented personal claims.

## Evidence on Hand

No real biography, projects, achievements, contact details, photography, or brand
assets were supplied. The site must not present starter content as verified fact.

## Product Principles

- Make the student's work understandable within one short visit.
- Prefer honest starter content over fabricated accomplishments.
- Keep editing and deployment approachable for a beginner.
- Make accessibility and responsive behavior part of the baseline.
- Let project highlights carry more weight than decorative interface chrome.

## Brand Commitments

Use GitHub Primer's interface language, semantic color tokens, component patterns,
and light/dark theming. GitHub references should describe the hosting platform or
link to the student's profile; they must not imply endorsement or ownership by
GitHub.

## Accessibility & Inclusion

Use semantic structure, visible keyboard focus, sufficient color contrast,
reduced-motion support, descriptive links, and responsive layouts.
